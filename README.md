# SigRoute — FPGA 信号路由追踪（VSCode 插件）

解决 FPGA 开发中最耗时的一类问题：**一根信号穿过、串接、并联了多个模块，还被改了名字，想知道它从哪来、到哪去、穿越了谁。**

选中信号 → 一键得到完整的跨模块路由链路（含每次改名点），可直接跳转到源码。

---

## 安装

到 [Releases](https://github.com/zh89468y/sigroute/releases) 下载最新的 `.vsix`（当前版本直链：[sigroute-0.3.6.vsix](https://github.com/zh89468y/sigroute/releases/download/v0.3.6/sigroute-0.3.6.vsix)），然后：

| 方式 | 操作 |
|---|---|
| 界面安装 | 扩展面板 → 右上角 `...` → **从 VSIX 安装…** → 选刚下载的 `.vsix` |
| 命令行 | `code --install-extension sigroute-0.3.6.vsix` |

装好后打开含 Verilog / SystemVerilog 的工程，等状态栏右下角出现已索引模块数即可用。

- 要求 VSCode `^1.85`；插件**零运行时依赖**，安装不会触发任何额外下载。
- 从源码构建：`npm install` → `npm run package`；自检 `node tools/selftest.mjs`（137 项断言，含 Webview 与 MCP 协议冒烟）。
- 给 AI agent 用的接口（MCP / 命令行）见下文「给 AI agent 用」一节，零依赖、无需构建。

## 使用方式

### 编辑器内（高频，且不打断面板）

| 操作 | 效果 |
|---|---|
| **悬停信号** | 位宽 / 方向 / 驱动源 / 负载 / 上级连接 / **层次路径** / **同网络别名**，**每一条都可点击跳转** |
| **悬停端口** | 额外给出「上级模块连接」—— 点击直接跳到父模块里例化本模块、连接该端口的位置 |
| **Ctrl+点击** | 跳到声明处（端口 / 内部信号 / 子模块端口 / 例化处的模块名），落点精确选中该标识符并短暂闪烁高亮 |
| **Shift+F12** | 查找引用：本模块内的驱动源与负载 **+ 同一网络在其它模块里的使用点**（改名后也能查到另一半） |
| 光标停在信号上 | 同文档同名信号自动高亮（词法分析结果按文档版本缓存，不再每次重算） |
| 模块声明行 CodeLens | `12 端口 · 8 例化 · 被例化 3 次` + `模块信息` 入口，不选信号也能进入分析 |
| 右键 → `跳到父层连接处` | 端口在多个地方被例化时，弹列表选择跳到哪一处 |
| 右键 → `复制信号层次路径` | 一次拿到 `top.u_a.u_b.s_data`（多处例化时列出全部候选） |
| 右键 → `查找同网络别名` | 这根线在别的模块里叫什么、什么方向、在哪一行，点选即跳 |
| 右键 → `追踪模块端口…` | 从当前模块的端口列表里挑一个开始追踪 |

| 快捷键 | 效果 |
|---|---|
| `Ctrl+T` 或 `Alt+Q` | 追踪上游 + 下游（只在 Verilog/SystemVerilog 编辑器里生效） |
| `Ctrl+Alt+↑ / ↓` | 只追上游 / 只追下游 |
| `Ctrl+Alt+P` | 跳到父层连接处 |
| `Ctrl+Alt+C` | 复制信号层次路径 |
| `Ctrl+Alt+F`（树视图内） | 切换过滤：全部 → 只看跨模块 → 只看改名 |

> **装了别的 Verilog 扩展时**（它们也注册了「转到定义」）：VSCode 会把多家结果合并，
> 只要多于一个就按"多处定义"处理，默认弹候选预览窗而不是直接跳。
> 要一直是直接跳，运行命令 `SigRoute: Ctrl+点击直接跳转（多处定义不再弹预览）` ——
> 它把 VSCode 的 `editor.gotoLocation.multipleDefinitions` 设为 `goto`（通知里可一键恢复）。
> 只有一个结果时 VSCode 本来就直接跳，不会弹窗。

> 悬停、跳定义、找引用都是**只读查询**，不会改变面板里正在追踪的主信号 ——
> 可以在盯着一根信号的同时，随手悬停查看其它信号，看完面板还是原来的内容。

### 面板（深度分析）

| 操作 | 说明 |
|---|---|
| 光标放在信号上 → `Ctrl+T` / `Alt+Q` | 追踪上游 + 下游（树视图） |
| 右键菜单 → `追踪信号并显示框图` | **一步得到模块框图** |
| 命令面板 `SigRoute:` | 框图、按信号名追踪、层次路径、同网络别名、导出 Mermaid / Markdown、重建索引、查看模块信息 |
| `SigRoute 信号路由` 面板（资源管理器内） | 点击树节点跳到源码；标题栏可切换过滤 / 切换视图 / 导出 Mermaid / 重建索引 |
| `SigRoute 信号脑图` 面板 | 同一份结果的脑图形态（见下文），标题栏一键与树视图互换 |
| 状态栏右下角 | 显示已索引模块数，点击重建 |

### 树视图的标记含义

| 标记 | 含义 |
|---|---|
| 🔶 **改名** | 信号在此处换了名字（如 `o_data` ⇄ `s_data`）—— 这正是最消耗人力的地方 |
| **位选** | 只使用了信号的一部分位（`s_data[7:0]`） |
| **不完整** | 表达式/拼接/黑盒，静态分析无法完整还原 |
| **过程块** | 由 `always` 块驱动或使用 |
| **模块内** | 模块内部的中间变量传播，非跨模块跳转 |
| **多路径** | 该模块被多处例化，存在多个可能的层次路径 |
| **已展开** | 该信号在上方已经展开过（防环、防重复） |
| **悬空** | 端口连接为空 `( )` |
| **可展开** | 该层分支超过上限被收起，点这一行可以继续展开（每点一次放宽 4 倍） |

### 树视图的过滤与摘要

标题栏的过滤按钮在三态间循环（树视图内 `Ctrl+Alt+F`）：

| 过滤 | 效果 |
|---|---|
| `全部` | 原样展示每一跳 |
| `只看跨模块` | 跳过模块内部的中间变量，把它们后面的跨模块节点**提升**上来 —— 一眼看清"穿越了谁" |
| `只看改名` | 只留改名点及其后续分支 —— 排查"名字从哪变成现在这样" |

树的第一行固定是**链路摘要**：模块数、改名处数、黑盒数、不确定点、最大跨模块层数，
以及"经过模块"的顺序 —— 先看全局规模，需要细节再往下展开。

> 过滤会改变可见层级，所以插件自己维护了一份"可见父节点"关系，
> 保证 `reveal`（以及框图的"在树中定位"）总能落到正确的行上。

### 脑图视图（与树视图一键切换）

树视图逐条点开看细节，脑图看整体形状：**根在最上，逐层向下缩进**，
上游绿、下游紫、改名橙加粗、黑盒黄虚线；分支长度就是链路深度。

> 为什么不画成"中间一个根、左右发散"的辐射图：这个视图住在资源管理器侧栏里
> （宽度通常两三百像素），辐射式需要横向空间，塞进去只会看到几个挤在一起的方块。
> 竖向布局把宽度让给文字、把长度交给纵向滚动，窄栏里才真正读得出来。
> 需要看模块级拓扑时用框图面板（那是横向的大图）。

**默认只展开"直接关联两层"**（和树视图同一策略）：起点、上下游分组、直接关联的那一层展开，
再下一层先收起 —— 需要时再手动点开，避免一屏几十行把真正关心的几条淹掉。
只有一个子节点的链路会自动展开（那种点击没有信息量）。

| 操作 | 效果 |
|---|---|
| 标题栏 `切换树视图 / 脑图` | 两个视图互换（记住选择，重启后保持） |
| 点击一行 | 跳到源码；点橙色的"…另有 N 个分支"行 = 继续展开该分支 |
| 行首 `▾ / ▸` | 折叠 / 展开该分支（折叠时显示 `(+N)`） |
| `默认` | 回到默认的两层展开 |
| `展开 / 折叠` | 全部展开 / 只留下起点与上下游分组 |
| `导出` | 导出 SVG，可直接插入设计文档 |

> 同一根信号再次渲染（点"继续展开"、重新追踪）时会**保留你手动折叠出来的形状** ——
> 折叠状态按"子节点下标路径"记忆，不受节点重建影响。

> 脑图**不做过滤**：过滤是树视图的局部功能（它的入口在树视图标题栏），
> 两个视图互不影响 —— 在一边切换过滤不会让另一边的内容变样。

## 框图可视化（类 Vivado BD，但更简化）

树视图回答"每一跳的确切细节"，框图回答"整体拓扑一眼看清"。

```
[mem_rd_ctrl]  ==o_data => s_data==>  [data_path ★起点]  ==s_data => i_data==>  [transfer_top]
        上游                                              起点模块                                              下游
```

### 图的语义

| 元素 | 含义 |
|---|---|
| **节点** | 模块（去重；同一模块在链路上多次出现只画一个，标注 `×N`） |
| **节点第二行** | **真实例化名**（如 `实例 u_b`）；悬停显示"在哪个模块中被例化"及同一模块的其它例化名 |
| **层次框** | 同一个父模块下、同一列且相邻的兄弟实例（虚线框），标签写明 `xxx 内的同层实例：u_a, u_b`。看到框 = 同层次；跨框的连线 = 跨层次 |
| **边** | 信号的**一次跨模块流动**，label = `源信号名 → 目标端口名`，改名处橙色加粗；悬停显示"经由实例" |
| **起点模块** | 第 0 列，高亮边框 + `起点` 角标 |
| **上游** | 排在左（或上），越远越靠外 |
| **下游** | 排在右（或下），越远越靠外 |

> 框图节点是模块级的（同一模块的多个实例合并成一个方块），所以"包含关系"用两层信息表达：
> 方块上的**例化名**说明"它是被谁、以什么实例名引进来的"；
> **层次框**把同一父模块下的兄弟实例圈在一起。要**按实例路径完全展开**（同名模块的不同实例各画一个方块）
> 属于下一步（见"已知局限"）。

**模块内部的 `assign` / `always` 传播不画成边** —— 这是"简化"的关键：只呈现"信号穿越了哪些模块"。

### 三个让它保持简洁的机制

| 机制 | 作用 | 实测（`s_data`） |
|---|---|---|
| **跳数裁剪** | 只保留距选中信号 N 层以内的连接。跳数按**信号实际传播层数**算，不是"图上的列距离"——`data_path` 与 `mem_ctrl` 在图上相邻，但这根信号要逆向 7 层才追到它 | 默认 1 跳：**3 个模块 / 2 条连线** |
| **并行边合并** | 多通道总线的 4~8 条同向连接合并为一条，标 `×N` | 271 条 → 53 条（全部跳数时） |
| **节点预算** | 复用树视图的 `maxNodes` / `maxChildren` 保护 | 大扇出信号不会卡界面 |

### 交互

| 操作 | 效果 |
|---|---|
| 点击方块 | 跳到该模块定义 |
| **双击方块** | 在树视图 / 脑图里定位到对应节点（被过滤掉时会自动切回"全部"） |
| 点击连线 | 跳到连接处源码（例化语句） |
| **双击连线** | 在树视图 / 脑图里定位到对应节点 |
| **信号清单** | 右侧列出链路上出现过的所有网络名，点一下就以它为新起点重新追踪 |
| **层次框** | 开关"同一父模块下的兄弟实例"虚线框 |
| 悬停节点 | 例化调用（哪个实例、在哪个模块中）、流入/流出信号、被经过次数、文件行号 |
| 悬停连线 | 信号名变化、端口名、经由实例、并列连接数、全部信号清单 |
| 悬停时 | 自动高亮该节点的所有关联边，其余淡出 |
| 滚轮 / 拖拽 | 缩放 / 平移（换信号时保持视角，不会突然跳走） |

## 给 AI agent 用（MCP / 命令行）

AI 读 RTL 最费 token 的从来不是"看懂一行代码"，而是那几个跨文件的问题：
**这根信号从哪来、到哪去、穿过了谁、在哪儿改了名**。这里把插件同一套解析/追踪引擎
（`src/core`）开放成两种形态 —— 结论与插件里显示的完全一致，不会出现"两套结果对不上"。

| 形态 | 入口 | 适合 |
|---|---|---|
| **MCP 服务**（stdio） | `node tools/mcp.mjs --root <工程目录>` | CodeBuddy / Claude Code / Cursor 等直接挂载 |
| **命令行** | `node tools/ai.mjs <操作>` | 任何能跑 shell 的 agent；也可以自己手敲 |

两者都**零依赖**：不需要 `npm install`、不需要编译（Node ≥ 22.6 的原生 type stripping）。

### 挂到 AI 客户端

```bash
node tools/mcp.mjs --print-config --root /path/to/your/rtl/project
```

它会把路径填好并打印出配置片段，塞进客户端的 `mcpServers`（Cursor 是 `mcp.json`）即可：

```json
{
  "mcpServers": {
    "sigroute": {
      "command": "node",
      "args": ["/abs/path/to/sigroute/tools/mcp.mjs", "--root", "/abs/path/to/your/rtl/project"]
    }
  }
}
```

> **只装了插件、没 clone 仓库？也可以。** 0.3.0 起 vsix 里就带着这两个文件，
> 把配置里的路径换成扩展目录即可（跑的是 `out/` 编译产物，与插件同一份代码，不需要装依赖）：
>
> ```
> node <扩展目录>/tools/mcp.mjs --root <你的工程>
> # Windows: %USERPROFILE%\.vscode\extensions\sigroute.sigroute-<版本>\tools\mcp.mjs
> ```
>
> 升级插件后记得把 `<版本>` 同步成新装的版本号 —— 旧版目录仍留在磁盘上，
> 路径不会报错、但跑的是旧代码（这个坑很隐蔽）。嫌麻烦的话，路径直接指向仓库里的
> `tools/mcp.mjs`，就永远不用同步了。
>
> 仓库里运行时：优先用 `out/`（编译产物），若 `src/` 比 `out/` 新（改了源码还没编译）会自动
> 回退到源码（此时需要 Node ≥ 22.6）；`SIGROUTE_AI_RUNTIME=src|out` 可强制指定。

### 多个工程 / 跟随工作区

**不用把工程写进配置** —— 服务默认跟随 AI 客户端声明的工作区（MCP `roots`，即 IDE 打开的项目）；
问不到工作区时才退回 `--root` / 当前目录。任何一次调用还能显式切工程：

```jsonc
// 8 个工具都支持在参数里带 root
{ "name": "sigroute_trace", "arguments": { "signal": "s_mid", "module": "top",
  "root": "D:/work/my_rtl_project" } }
```

各工程各自建索引（LRU 保留最近 4 个），换工程**不用重启服务**；`sigroute_index` 会报出
当前已索引的工程根清单。命令行同理 —— `--root` 只是"默认根"，可以省略。

### 八个工具（AI 视角：一次调用换掉十几次 grep）

| 工具 | 回答什么问题 |
|---|---|
| `sigroute_index` | 工程多大、顶层是谁、识别了哪些宏 |
| `sigroute_search` | 名字记不全 → 精确名字 + 位置（支持 `*` `?` 通配） |
| `sigroute_describe` | 这是什么、谁驱动它、谁在用它（一跳速查，最便宜） |
| `sigroute_trace` | 从哪来、到哪去、穿过哪些模块、哪儿改名（跨模块链路树 + 摘要） |
| `sigroute_aliases` | 这根线在别的模块里叫什么（改名反查 / 网络等价类） |
| `sigroute_hierarchy` | 完整层次路径 `top.u_a.u_b.sig`（多处例化时列全部候选） |
| `sigroute_module` | 端口表（方向/位宽/行号）、子例化、被谁在哪儿例化 |
| `sigroute_context` | 给 `文件:行` → 该处信号 + 附近声明 + 链路（读陌生代码的第一入口） |

> **约定**：行号一律 **1 起**、路径 **相对工程根** —— 可以直接拿去喂 `read_file` / `grep`；
> 工程外的路径会被标成 `[工程外] <绝对路径>`，不会和工程内路径混在一起。
> 长驻的 MCP 服务按文件指纹**增量刷新**索引：你改完代码再问，看到的是新结果。
> `trace` 还支持 `filter=cross|renamed`（只看跨模块 / 只看改名，省 token）与 `graph`（模块级拓扑）。

### 命令行等价用法

```bash
node tools/ai.mjs index   --root <工程>
node tools/ai.mjs search  "s_data*"                       --root <工程>
node tools/ai.mjs describe s_data --module data_path      --root <工程>
node tools/ai.mjs trace    s_data --module data_path --direction both --filter cross --root <工程>
node tools/ai.mjs context  --file src/data_path.v --line 245 --root <工程>
node tools/ai.mjs --help                                   # 全部操作与参数
```

加 `--json` 得到结构化结果（便于脚本化 / 二次处理）。

## 工作原理

```
词法分析 (lexer.ts)
  ├─ 正确处理注释 / 字符串，避免把注释里的例化当真
  ├─ 收集 `define / `include / `undef
  └─ 依据宏裁剪 `ifdef / `ifndef / `elsif 分支（被裁掉的 token 标记 inactive 而非丢弃）

结构解析 (parser.ts)
  ├─ 模块端口列表（ANSI 与传统两种风格，含方向 / 位宽 / 顺序）
  ├─ 例化及端口连接（命名连接 + 位置连接回填）
  ├─ assign / always 的数据流（语句级：`lhs <= reads`）
  ├─ 跳过 (* ... *) 综合属性（Xilinx 工程必备，否则端口解析会跑偏）
  ├─ `include 内联（inline.ts）：把 .vh 内容拼进解析流，并维护位置映射
  └─ 剔除非信号名（循环变量 i、genvar、parameter）

索引 (indexer.ts)
  ├─ 两遍扫描：先全局收集宏，再解析（保证 `ifdef 判定可靠）
  ├─ 模块表、文件→模块、模块→例化点（反查）
  ├─ 网络等价类（nets.ts）：并查集合并"父层网络 ≡ 子模块端口"→ 同一根线的全部别名
  ├─ 辅助声明文件：IP 例化模板只补端口方向，永不覆盖真实实现
  ├─ 保存时增量更新（只重解析改动文件，且只动它贡献的例化记录）
  └─ 磁盘缓存（cache.ts）：文件指纹 + 配置指纹一致时直接接管，跳过解析

路由图 (graph.ts)
  ├─ 端口等价边：模块端口的"内部名"与"外部名"是同一个物理网络
  ├─ 实例连接边：父层 net → 子模块端口
  ├─ 驱动边：assign / always / 子模块 output
  ├─ 每个 (模块, 信号, 方向) 只展开一次：既防组合环又防树爆炸
  └─ 节点预算 + 分支上限（可交互放宽）：保护界面流畅

层次路径 (hierarchy.ts)
  └─ 沿"谁例化了我"向上爬到顶层，给出 `top.u_a.u_b.sig`（多处例化时列全部）
```

### 关键设计取向

**宁可标注"不确定"，也不编造精确结果。** 静态分析无法替代 RTL elaboration，
所以每个可疑之处都会被显式标记（`不完整` / `多路径` / `方向未知`），
而不是给出一个看起来确定、实则错误的链路。

## 配置项

| 配置 | 默认值 | 说明 |
|---|---|---|
| `sigroute.includeGlobs` | `**/*.v` `**/*.sv` `**/*.vh` `**/*.svh` | 参与索引的文件 |
| `sigroute.excludeGlobs` | 排除 Vivado 输出目录 + `*_sim_netlist.v` | **保留 IP 的 `*_stub.v`**，它是判断 IP 端口方向的唯一依据 |
| `sigroute.defines` | `[]` | 额外认为已定义的宏 |
| `sigroute.undefines` | `[]` | 强制视为未定义的宏（优先级最高） |
| `sigroute.honorIfdef` | `true` | 是否尊重条件编译 |
| `sigroute.maxDepth` | `30` | 最大跨模块层数 |
| `sigroute.maxNodes` | `600` | 单次追踪节点总数上限 |
| `sigroute.maxChildren` | `24` | 单节点分支上限 |
| `sigroute.mermaidDirection` | `LR` | Mermaid 图方向 |
| `sigroute.autoShowGraph` | `false` | 每次追踪后自动打开框图 |
| `sigroute.graphDirection` | `LR` | 框图初始方向（面板内可切换） |
| `sigroute.graphHops` | `1` | 框图默认跳数：1 = 只显示直接关联；0 = 不裁剪 |
| `sigroute.hover.enabled` | `true` | 是否启用编辑器内的悬停速查 |
| `sigroute.hover.sections` | `decl` `drivers` `loads` `parent` `path` `aliases` | 悬停信息框显示哪些小节（顺序即显示顺序，清空则只留信号名） |
| `sigroute.hover.maxRefs` | `12` | 每一节最多列几条 |
| `sigroute.hover.maxLines` | `40` | 整个悬停信息框的行数上限（超出按节截断并提示） |
| `sigroute.inlineIncludes` | `true` | 把 `` `include`` 内容内联进解析（端口列表写在 `.vh` 里的工程需要它） |
| `sigroute.blackboxSources` | `**/*.veo` `**/*.vho` | 只用于补齐黑盒 IP 端口方向的辅助文件 |
| `sigroute.codeLens` | `true` | 模块声明行的 CodeLens（规模摘要 + 追踪入口） |
| `sigroute.indexCache` | `true` | 索引结果落盘：重启后指纹未变则跳过解析 |

> 宏定义会自动从工程中未被注释的 `define`（含 `include` 的 `.h`）收集，
> 所以 `module_switch.h` 里 `// \`define MEASURE_ON` 这种注释掉的功能会自动视为关闭。

## 已知局限（M1 范围）

| 局限 | 现状 | 后续 |
|---|---|---|
| 参数化 / `generate` 展开 | 不展开参数；`generate for` 的实例名已还原为 `label[i].u_x` | 接 elaboration 后端 |
| 位级精确追踪 | 只做网络级 + 位选标注 | 接 Verilator / Vivado |
| 黑盒 IP 端口方向 | 靠 `*_stub.v` 与例化模板（`sigroute.blackboxSources`）推断；都没有时标注"方向未知" | 支持读取 `.xci` / `.edf` |
| `assign` 内的函数调用 | 不深入，标记"不完整" | — |
| 同一模块多处例化 | 按模块去重（不按实例路径展开），标记"多路径"；框图中合并为一个节点并标 `×N` | 可选按实例路径展开 |
| 框图节点粒度 | 模块级；同名模块的多个实例会合并成一个方块 | 按实例路径展开 |
| `` `include`` 内联的位置 | 来自 `.vh` 的内容（如端口列表）跳转会落在 `include` 指令行，而不是 `.vh` 内部 | 给每个数据结构带上文件名 |
| VHDL | 不支持 | 单独的后端 |

**能消除以上大部分局限的下一步**：接入 RTL elaboration 后端
（工程里已有 `.xpr` 的话，调用 Vivado `link_design` 导出 elaborated 网表是最准的路径）。
